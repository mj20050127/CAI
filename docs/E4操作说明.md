**E4 操作说明：基础增强 + CutMix**

E4 已完成正式 100 轮，运行路径为 `runs/E4/seed42_retry1`。第 97 轮最佳验证准确率为 96.30%，已用完整验证集复算。以下命令用于复现或检查结果。详细结果见 [E4 对照分析](../results/E1_vs_E4/analysis.md)。

本次保留 E1 的随机裁剪和水平翻转，单独加入 CutMix（alpha=1.0、每个训练 batch 应用）。主要对照为 E1/E4，补充比较为 E3/E4。E1 与 E3 最佳验证准确率分别为 95.30% 和 95.62%。

其余保持 E1：100 轮，batch=128，SGD lr=0.1 / momentum=0.9 / weight decay=0.0005，余弦至 0.00001，Dropout=0.3，AMP，num_workers=0，训练种子 42。训练 / 验证 / 监测数量仍为 45,000 / 5,000 / 5,000，使用相同划分、类别顺序及归一化。

E4 从 E1 第 0 轮 initial.pt 加载相同初始模型，仅加载参数和 BN 缓冲状态，重新创建优化器和调度器，不接着 E1/E3 训练后的权重继续。缺少来源文件时应恢复对应的 initial.pt，不能替换成 best.pt 或 last.pt。

**二、理解实际面积与训练指标。**

每个 batch 先完成基础增强，再抽取 lambda_raw ~ Beta(1,1)，随机配对和矩形中心，以矩形区域替换图片内容。每批共用一个矩形；取整与边界裁剪后，必须重新计算：

```text
actual_area = (x2 - x1) * (y2 - y1)
lambda_eff = 1 - actual_area / (32 * 32)
loss = lambda_eff * CE(logits, yA)
       + (1 - lambda_eff) * CE(logits, yB)
```

本地 GPU 合成检查中，一批抽样 lambda_raw≈0.50004，但边界裁剪后替换区域只有 330 像素，所以最终 lambda_eff=0.677734375，目标标签为 A 约 67.77%、B 约 32.23%。程序使用后者计算损失和加权准确率。

矩形使用 [y1:y2,x1:x2] 半开切片，奇数边长按 left+cut_w / top+cut_h 得到另一端，再裁剪边界；复制来源为未修改的原 batch，避免区域被重复污染。空区域对应 lambda_eff=1、整图替换对应 0，均作为合法边界情况处理，不重新抽样筛选。

方法与面积修正依据见 [CutMix 原论文](https://arxiv.org/abs/1905.04899)及[作者实现](https://github.com/clovaai/CutMix-PyTorch/blob/master/train.py)。本项目的具体整数框规则与测试约定见 [E4实验方案](E4实验方案.md)。

CutMix 使用软标签，训练 loss 不需要接近 0。训练加权准确率也不是普通单一标签准确率；与 E1/E3 判断优劣时使用相同口径的干净训练监测和完整验证指标。

**三、启动正式 100 轮。**

```powershell
.\.venv\Scripts\python.exe -u train.py --config configs/e4.json --run-name seed42_repro
```

启动时应显示正式 E4、cifar_resnet18、基础增强“随机裁剪 + 随机水平翻转”、CutMix alpha=1.0 / 应用概率=1.0，以及 E1 第 0 轮的初始参数哈希。首次依赖导入和数据校验需要等待。

`runs/E4/seed42` 保留了首次中断的记录。实际完成的重跑使用了 `--run-name seed42_retry1`，上述复现命令会写入新的 `runs/E4/seed42_repro`。每次运行保存 initial.pt、best.pt、last.pt、配置、数据清单、源文件快照和逐轮日志。

新增记录如下：

| 文件 / 字段 | 作用 |
|---|---|
| cutmix_batches.csv | 每批 epoch、batch、lambda_raw、lambda_eff、x1/y1/x2/y2、actual_area 和 applied |
| train_cutmix_weighted_accuracy | 按实际面积加权两份标签的训练正确率 |
| cutmix_batches / cutmix_total_batches | 本轮执行 CutMix 的批数与总批数 |
| cutmix_nonzero_batches | 实际替换面积大于 0 的批数；区别于尝试执行批数 |
| cutmix_lambda_mean / min / max | 本轮已应用批次的实际 lambda_eff 汇总 |
| summary.json | CutMix 参数、训练指标口径、初始来源、最佳结果与完成状态 |

正式每轮 352 批，末批 72 张；100 轮应产生 35,200 条 CutMix batch 记录。程序同时把这些记录写入 checkpoint，用于中断恢复。

若你希望先手动执行小规模流程检查，可运行：

```powershell
.\.venv\Scripts\python.exe -u train.py --config configs/e4.json --smoke
```

它使用 1,000 / 500 / 500 张训练、验证、监测图片，默认 2 轮，单独输出到 runs/E4/smoke_seed42/。之后正式训练仍从第 0 轮开始；小规模指标不用于正式对照，也不据此改变 E4 的其他参数。

**四、中断后恢复。**

```powershell
.\.venv\Scripts\python.exe -u train.py --config configs/e4.json --run-name seed42_repro --resume
```

从 E4 自己的 initial.pt 和 last.pt 核验、恢复模型、优化器、学习率、AMP scaler、随机状态和矩形日志。已开始的续训不需要重新读取外部 E1 初始文件，但应保留原配置中的路径和参数。改变 alpha、概率、总轮数等后会拒绝混用原运行。

派生 CSV 缺失时，续训会从 last.pt 中的完整记录重建。CutMix batch 记录数必须与已完成轮次及每轮批数一致。完成 100 轮后再次 --resume 会提示完成并保留结果。

**五、训练结束后评估与对照。**

```powershell
.\.venv\Scripts\python.exe plot_history.py --run-dir runs/E4/seed42_retry1
.\.venv\Scripts\python.exe evaluate.py --checkpoint runs/E4/seed42_retry1/best.pt
.\.venv\Scripts\python.exe compare_runs.py --run-dirs runs/E1/seed42 runs/E4/seed42_retry1
.\.venv\Scripts\python.exe compare_runs.py --run-dirs runs/E3/seed42 runs/E4/seed42_retry1
```

验证默认不执行 CutMix 或 MixUp，只使用原始单一标签。最佳权重仍按验证准确率优先、loss 次之选择，轮次不一定为 100。

- E1/E4 输出 results/E1_vs_E4/，记录 comparison_kind=cutmix，差值为 E4−E1。
- E3/E4 输出 results/E3_vs_E4/，记录 comparison_kind=mixup_vs_cutmix，差值为 E4−E3。

两类对照都检查相同数据清单、基础增强、模型、参数量、初始状态和其他训练协议。E3/E4 明确是两套预设混合方法方案比较：MixUp alpha=0.2，CutMix alpha=1.0，不能解释成有效混合强度完全相同。报告和曲线注明各自训练 loss 口径，统一比较验证结果。

E2/E4 同时改变基础增强与 CutMix，工具拒绝将其作为单因素对照。已有 E0/E1、E1/E2、E1/E3 对照仍兼容。

**实现检查与边界。**

实现检查位于 [results/implementation_checks/E4/](../results/implementation_checks/E4)。最终全量 **88 项检查全部通过**，覆盖面积与像素、损失及梯度、训练指标、边界情况、续训和旧实验兼容性；另与 E3 冻结的旧 engine 做 CPU 合成对照，普通训练和 MixUp 的参数、输出与 NumPy 随机状态一致。GPU 检查仅使用一个合成 batch，不代表正式 E4 表现。示例图也只使用训练索引。
