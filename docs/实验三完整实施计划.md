官方 CIFAR-10 训练集包含每类 5,000 张图片，测试集包含每类 1,000 张，因此可以进行上述分层划分。[数据集官方说明](https://www.cs.toronto.edu/~kriz/cifar.html)

- 数据划分种子固定为 2026，训练监测子集种子固定为 2027；保存索引、类别顺序和文件校验信息。训练随机种子使用 42、43、44，改变训练种子时保持数据划分不变。
- 32×32 分支的归一化均值、标准差仅由 45,000 张训练图片在无随机增强条件下计算并保存。教师给出的 0.5/0.5 是可用的示例；本方案选择保存实际训练统计量。
- 基础增强使用 RandomCrop(32, padding=4) 和水平翻转 p=0.5；验证、测试和干净训练监测均采用确定性预处理。
- 训练数据与验证数据分别管理预处理，防止修改共享数据对象时把训练增强带入验证。
- 使用测试集之前冻结实验列表、超参数、各次运行的 checkpoint 和模型选择规则。测试结果用于报告；后续分析误分类与热力图不再反向用于调参。

模型分为四个明确的实现对象，各自承担不同实验用途。

| 模型 | 建议结构与输入 | 作用 |
|---|---|---|
| 自建 CNN | 输入 3×32×32；三个卷积块，通道 64/128/256；每块两次 3×3 卷积、BatchNorm、ReLU，之后 2×2 池化；全局平均池化、Dropout 0.3、十分类输出 | 满足自行设计要求，作为结构比较基线 |
| CIFAR ResNet-18 | 输入 32×32，首层为 3×3、步长 1、padding 1，入口跳过最大池化，四个残差阶段，十分类头 | 主实验模型，承载增强、注意力、损失、优化策略和 32×32 预训练对照 |
| 标准 ResNet-18 | 保留标准网络入口，输入 224×224，仅更换十分类层；分别随机初始化和加载 ImageNet 权重 | 配对分析预训练的作用 |
| MobileNetV3-Small | 输入 224×224，加载 ImageNet 权重并更换十分类输出层 | 补充轻量模型方案的准确率、参数量和实际速度比较 |

上述 CIFAR 入口改动是本方案的设计选择。模型输出使用 logits，交叉熵前不额外执行 softmax；报告展示置信度时再计算概率。

224×224 分支的标准 ResNet 和 MobileNet 在验证、测试时采用对应官方权重的预处理，包括缩放至 256、中心裁剪至 224，以及使用 ImageNet 均值和标准差。训练时在原始 32×32 图像上随机裁剪、翻转，再缩放至 224 并作同样的归一化。E9/E10 共用这套预处理，E4、E11 和 E11_stem 共用 CIFAR-10 的 32×32 预处理。具体预处理应随权重名称和库版本一起记录。 [ResNet-18 官方说明](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html) · [MobileNetV3-Small 官方说明](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.mobilenet_v3_small.html)

首轮安排 E0–E12 和 E11_stem，共 **14 套配置**。带余弦调度的 E1 是增强、注意力和优化策略实验的共同对照，E6 使用固定学习率。E4 是 E11 和 E11_stem 两种 32×32 预训练方案的共同对照。

E0/E1 使用共享训练方案比较架构。E9/E10 使用相同的标准 ResNet-18、分类头初值、224×224 输入和训练条件，均执行全量训练。种子 42 的最佳验证准确率分别为 **92.00%** 和 **96.12%**。该结果衡量标准 ResNet-18 在这套 224×224 配置下的预训练收益。E4、E11 和 E11_stem 用相同的 32×32 CIFAR ResNet-18 比较三种初始化方式。E10/E12 比较两套预训练模型方案，报告应注明各自的预训练权重来源和流程。 [E9/E10 实测对照](../results/E9_vs_E10/comparison.json)

这些参数作为待短跑确认的起点。正式实验前允许根据稳定性和显存统一调整；调整后冻结配置，对受影响的对照组使用同一版本。

| 设置 | 32×32 主实验（含 E4、E11 和 E11_stem） | 224×224 标准 ResNet 与轻量模型分支 |
|---|---|---|
| 最大轮数 | 100 | 30 |
| batch size | 128 起步 | 32 起步 |
| 优化器 | SGD，momentum=0.9 | AdamW |
| 初始学习率 | 0.1（E11_stem 复验使用 0.01） | 0.0003 |
| weight decay | 0.0005 | 0.0001 |
| 学习率策略 | 余弦衰减至 0.00001；E6 固定初始值 | 余弦衰减至 0.000001 |
| 损失 | 普通交叉熵。E3 使用 MixUp 加权目标，E4、E11 和 E11_stem 使用 CutMix 加权目标，E8 使用标签平滑 | 普通交叉熵 |
| 混合精度 | GPU 支持且短跑稳定后统一启用 | 同左 |
| 验证频率 | 每轮一次 | 每轮一次 |
| checkpoint 选择 | 验证准确率最高；并列时选验证普通交叉熵更低者，再并列选更早轮次 | 同左 |
| 保存方式 | 每轮更新 last，改善时更新 best | 同左 |

若显存不足，应先为该对照组统一减小 batch size。预训练成对实验仍需保持一致。梯度累积可以维持有效 batch size，但 BatchNorm 统计仍受实际微批大小影响，因此不能仅凭有效 batch 相同就宣称条件完全一致。

100 轮和 30 轮是预算起点，不是保证充分收敛的结论。短跑结束后，基于实测耗时和基线验证曲线决定是否统一延长某一实验组；追加训练必须保留为新配置或明确版本，不能悄悄只延长有利的一组。迁移实验的结论限定为给定训练方案与预算下的比较。

各个加分方法需要落实到以下程度。

- **数据增强**记录原图、基础增强、MixUp 和 CutMix 示例。E3、E4、E11 和 E11_stem 在每个训练 batch 上执行相应混合，记录 alpha、实际混合系数和应用概率。CutMix 标签权重按裁剪到图像边界后的实际替换面积计算。两种方法都会产生软标签，需要匹配交叉熵计算。 [Torchvision 官方示例](https://docs.pytorch.org/vision/stable/auto_examples/transforms/plot_cutmix_mixup.html)
- **注意力**：在每个 ResNet BasicBlock 的第二次 BatchNorm 之后、与残差相加之前加入 CBAM，通道压缩率先取 16，空间卷积核取 7。记录插入位置、通道/空间权重计算和实际参数增量。共享骨干参数尽量从同一随机初始化状态加载，使注意力对照更清楚；新增参数单独初始化。[CBAM 原论文](https://openaccess.thecvf.com/content_ECCV_2018/html/Sanghyun_Woo_Convolutional_Block_Attention_ECCV_2018_paper.html)
- **学习率**：展示 E1/E6 的实际学习率曲线、验证曲线和最终指标。学习率随 epoch 更新，记录调用位置和实际取值，避免偏移一个 epoch。[PyTorch 余弦调度说明](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.CosineAnnealingLR.html)
- **早停**：E7 最少训练 60 轮，在该时点开始累计等待；之后验证准确率连续 15 轮没有超过监控最佳值 0.001，即 0.1 个百分点，停止训练。达到 100 轮仍未触发则正常结束。最终仍按统一规则选择 best checkpoint。报告实际停止轮数、验证和测试性能、实际训练时间，早停未触发也如实记录。
- **损失改进**：标签平滑采用 epsilon=0.1；对于 10 类，目标分布按 q=(1-epsilon)×one_hot+epsilon/10 构造。普通交叉熵与平滑交叉熵分别介绍；这是对成熟方法的应用，不声称发明新损失。[PyTorch 损失函数说明](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)
- **预训练**使用可追溯的官方权重，记录权重枚举、来源和校验值。E10 使用标准 ImageNet 骨干和 E9 的十分类头初值。E11 在 CIFAR 版模型上迁移四个残差阶段，使用 E4 的入口和分类头初值。E11_stem 也迁移适配后的 `conv1` 和 `bn1`。各组微调均更新全部可训练参数。 [官方迁移学习教程](https://docs.pytorch.org/tutorials/beginner/transfer_learning_tutorial.html)

## E11 同架构预训练对照

E4 是当前 32×32 主模型的直接基线。种子 42 的正式运行 `runs/E4/seed42_retry1` 在第 97 轮取得 **96.30%** 的最佳验证准确率。E11 检验的是，在 E4 已使用 CutMix 的条件下，把四个残差阶段从 ImageNet 权重起步，能否提升验证准确率。 [E4 验证分析](../results/E1_vs_E4/analysis.md)

| 对照条件 | E4 与 E11 的约定 |
|---|---|
| 架构和输入 | 同一 CIFAR ResNet-18，32×32 RGB 输入，3×3 首层卷积，无入口最大池化，Dropout 0.3，十分类头 |
| 共同的第 0 轮参数 | 两组的 `conv1`、`bn1` 和 `fc` 均取 E4 的第 0 轮状态，包括相应缓冲区 |
| 被检验的变量 | E4 使用随机初始化的 `layer1` 至 `layer4`。E11 使用 `ResNet18_Weights.IMAGENET1K_V1` 中与这四个阶段匹配的参数和缓冲区 |
| 数据与随机性 | 固定 45,000/5,000 划分、归一化统计及干净训练监测集。正式种子为 42，核对两组初始随机状态与 DataLoader 生成器状态以复现训练顺序和增强序列 |
| 增强与损失 | 两组在 32×32 上执行随机裁剪和水平翻转，每个训练 batch 使用 CutMix，`alpha=1.0`、应用概率 `1.0`。交叉熵按裁剪到图像边界后的实际替换面积加权 |
| 训练预算 | 两组全量训练 100 轮，batch 128，SGD，初始学习率 0.1，momentum 0.9，weight decay 0.0005，余弦衰减至 0.00001，CUDA AMP |
| 权重选择 | 验证准确率最高者优先，同准确率时用验证普通交叉熵及较早轮次决定 |

E11 先读取 `runs/E4/seed42_retry1/initial.pt`，再加载已经缓存的官方权重 `data/weights/resnet18-f37072fd.pth`。ImageNet 权重只覆盖 `layer1` 至 `layer4` 中同名、形状和类型匹配的张量。对官方权重中缺少的 BatchNorm 计数缓冲区，沿用 E4 第 0 轮记录。加载后核对 E4 来源和官方文件的 SHA-256、两组入口及分类头的逐张量相等，以及 E11 第 0 轮残差参数确实来自预训练。已完成的 E11 正式运行位于 `runs/E11/seed42_retry1`。

在项目根目录先用小样本检查权重加载、前后向、保存与续训。已按以下命令完成两轮，记录保存在 `runs/E11/smoke_seed42`。如需再做一组冒烟，在两条命令中都指定同一个新运行名。

```powershell
.\.venv\Scripts\python.exe -u train.py --config configs/e11.json --smoke --stop-after 1
.\.venv\Scripts\python.exe -u train.py --config configs/e11.json --smoke --resume
```

两轮冒烟每轮只有 8 个更新批次，验证损失曾超过 26,000。随后用完整训练集做了一次内存中的首轮检查，同一初始学习率 `0.1` 下跑完 352 批后，验证损失为 **2.0584**，准确率为 **20.14%**。E4 的正式首轮为 **1.7985** 和 **31.46%**。E11 早期波动较大，最终收益以正式运行的验证数据为准。权重来源、CutMix 复现、续训和对照导出纳入了全量回归，141 项测试通过。 冒烟日志（`runs/E11/smoke_seed42/history.csv`）

E11 按 100 轮余弦训练计划完成正式运行。以下命令复现其正式训练、验证和对照，启动训练与续训使用同一个运行名。

## E11 首层适配对照

E11_stem 在 E11 的四个预训练残差阶段之前接入改为 3×3 的 ImageNet 首层和预训练 `bn1`。开发时核对 `conv1.weight` 的 7×7 空间维，取 `[..., 2:5, 2:5]`，中心区域的数值原样载入，得到 64×3×3×3 的 CIFAR 首层权重。`bn1` 和 `layer1` 至 `layer4` 加载官方 `ResNet18_Weights.IMAGENET1K_V1` 的权重及运行均值、方差。官方文件缺少的 BatchNorm 批次计数沿用 E4 第 0 轮记录。十分类头取 `runs/E4/seed42_retry1/initial.pt` 的原始参数。

E4、E11 和 E11_stem 共用 32×32 输入、CIFAR ResNet-18、Dropout 0.3、数据划分、种子 42、训练顺序和 CutMix 随机序列。每个训练 batch 的 CutMix 取 `alpha=1.0`、应用概率 `1.0`。原初始化对照的计划为 100 轮，batch 128，SGD 学习率从 0.1 按余弦衰减至 0.00001，momentum 0.9、weight decay 0.0005，开启 CUDA AMP。以下配对用于同学习率的初始化对照。

| 配对 | 比较的变量 | 结果用途 |
|---|---|---|
| E4 / E11_stem | E4 的随机骨干起点与迁移后适配的骨干起点 | 判断这套迁移是否超过 E4 的 96.30% 基线 |
| E11 / E11_stem | 同样的预训练残差阶段下，E4 的随机入口起点与适配后的预训练 `conv1`、`bn1` 起点 | 衡量加入入口迁移的合并效果，以 E11 的 95.50% 为参考 |

真实权重核验确认，入口首层等于官方中心裁剪、分类头与 E4 相同、四个残差阶段与 E11 相同。`0.1` 的 E11_stem 在 `runs/E11_stem/seed42` 完成了 5 轮，首轮验证准确率为 **10.98%**，第 5 轮为 **38.32%**。以相同的初始权重、训练数据及 CutMix 随机序列进行内存复验，`0.01` 下前 50 批平均训练损失从 6.5934 降到 2.0671，完成同样的 352 个批次后，首轮验证准确率达到 **84.32%**。

报告中的比较指标统一定义，尤其解决混合增强造成的训练准确率歧义。

| 指标 | 计算与记录方式 |
|---|---|
| train_objective | 在实际训练输入和训练目标上，按样本数加权平均的训练损失 |
| train_clean_loss / accuracy | 固定的 5,000 张训练监测图片，无增强，eval 模式，使用原始标签和普通交叉熵 |
| val_loss / accuracy | 固定 5,000 张验证图片，确定性预处理，原始标签和普通交叉熵 |
| test_accuracy | 正确预测数 / 10,000 |
| 每类准确率 | 真实属于该类且预测正确的数量 / 该类样本数；即该类召回率 |
| 混淆矩阵 | 行为真实类别，列为预测类别；同时输出计数版和按行归一化版 |
| 补充分类指标 | 每类 precision、recall、F1 和 macro-F1，可用于补充分析 |
| 模型成本 | 十分类模型实际参数量、权重文件大小、训练时长、峰值显存、推理延迟或吞吐率 |

训练监测子集是训练集的一部分，其用途和数量应写进图注；不将它冒充全训练集评估。MixUp/CutMix 的混合图片不直接使用原始单一标签计算普通准确率。不同训练目标的 loss 曲线分别说明，跨方法比较时使用统一的验证指标。

推理测试在同一设备、相同精度设置下进行，先预热，再做足够次数的同步计时，明确 batch size、输入分辨率及是否包含预处理。建议同时记录 batch=1 的延迟和相同固定 batch 的吞吐率。32 与 224 分辨率的结果标注条件，不能只凭参数少就断言实际更快。

重复实验分两阶段进行，避免一开始把每项配置都训练三遍。

1. 首轮使用训练种子 42，包含 E0 至 E12 和 E11_stem，共 14 次正式训练。
2. 若 E11_stem 的种子 42 验证结果值得复核，优先补 E4/E11_stem 的种子 43、44。每个种子先用该种子的 E1 第 0 轮权重启动 E4，再将同种子 E4 的第 0 轮权重用于配对迁移实验。E1、E4、E9、E10 和 E11_stem 各补两次时，计划合计 **24 次正式训练**。
3. 对上述五套配置报告各次结果、均值和样本标准差，并在同种子下列出配对差值。重复结果用于描述波动和检查收益是否复现。
4. 其余配置明确标注单种子结果。若最终准备推荐的模型不在五个复核配置中，在最终测试前为它补充重复实验；这部分另计预算。
5. 联调短跑、异常重跑和额外组合另计。若预算不足，优先保留 E1、E4 和验证表现较好的 32×32 迁移方案的重复，核心计划为 20 次，E9/E10 标注为单种子对照。预算允许时可另补 E5 的种子 43、44，分别和已有的同种子 E1 结果配对。

最终模型根据验证表现确定，优先比较已有三种子结果的候选；性能相近时结合模型成本和稳定性选择。代表性图片可固定展示种子 42 的结果。不要在看到测试结果后挑选最好的种子作为唯一主结果，也不要把多种子平均准确率描述成集成模型准确率。本方案默认保持 45,000/5,000 划分完成主报告。

可解释性安排在训练完成后进行，复用已保存模型，不增加独立训练任务。

- **Grad-CAM**：对 E1、E5、E11 选定 checkpoint 展示原图、热力图和叠加图。预测类别与真实类别的热力图分别标明目标类别。CIFAR ResNet 后段空间图较小，可同时检查 4×4 和 8×8 层；放大后的图只作为粗粒度定位解释。[Grad-CAM 原论文](https://openaccess.thecvf.com/content_iccv_2017/html/Selvaraju_Grad-CAM_Visual_Explanations_ICCV_2017_paper.html)
- **特征图**：固定同一张图片，展示浅层、中层和深层的若干通道；固定通道选择规则和色标说明，讨论表示变化。
- **注意力图**：可额外展示 E5 的空间注意力权重，与 Grad-CAM 区分标注；模块权重和类别归因图含义不同。
- **样本选择**：从每类中按固定种子抽取一张正确、一张错误样本，某类无错误时如实记录；补充若干高置信错误以及改进前后由错变对、由对变错的样本，记录原始样本索引。
- **分析问题**：目标是否过小、是否与背景混淆、是否存在相似纹理和轮廓、是否因低分辨率难以辨别。热力图提供定性线索，不能单独证明模型理解了物体，也不能代替准确率结果。

本机为 NVIDIA GeForce RTX 4060 Laptop GPU，约 8 GB 显存。E4、E9、E10 和 E11 的正式训练环境和实测耗时已有运行记录，E11_stem 以 E4 的运行记录核对设备和训练设置。 E4 环境记录（`runs/E4/seed42_retry1/environment.json`）

环境阶段先检查现有 Python/Conda 环境，选择兼容的 Python、CUDA 版 PyTorch 和 torchvision，在隔离环境中安装并锁定实测版本。用实际张量运算确认 GPU 可用。GPU 驱动支持的 CUDA 版本与 PyTorch 自带运行时版本分别记录。预训练权重下载和数据下载应校验并缓存。

算力预算以短跑实测计算：对自建 CNN、普通 CIFAR ResNet、CBAM 分支、224 ResNet 和 MobileNet 分别测量预热后至少 2–3 个完整 epoch，包含训练、训练监测、验证和保存成本。以各配置实际每轮耗时乘以计划轮数，得到总 GPU 占用时间，再保留约 20% 调度和重跑余量。另留开发、分析、报告和机器不可用时间，这些不由 GPU 小时直接推算。

在初始轮数下，首轮最多包含 1,100 个 32×32 训练 epoch 和 90 个 224×224 epoch。补齐上述五套配置的重复后，最多为 1,700 个 32×32 epoch 和 210 个 224×224 epoch。预算按各配置每轮的实测耗时分别估算，并计入早停、追加调参和组合修订的实际轮数。

若实际预算过大，先压缩额外组合和重复范围，保留每个加分方向及其必要对照；再为相应整个对照组统一调整训练预算。不能只删除 E9 却继续声称已经隔离了预训练的收益。数据下载、权重下载或环境配置出现问题时，优先推进本地随机初始化主实验，并记录待解决项。
