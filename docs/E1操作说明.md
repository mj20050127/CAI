**E1 操作说明：CIFAR ResNet-18 与 E0 架构对照**

截至 2026-11-16，E1 的真实 CIFAR-10 smoke 与正式 100 轮训练均已执行。正式训练的最佳权重来自第 96 轮，完整验证复算准确率为 95.30%，比 E0 的 93.46% 提高 1.84 个百分点；第 100 轮为 95.12%。完整对照见 [结果分析](../results/E0_vs_E1/analysis.md)。下述命令保留供理解过程和复现使用，现有训练无需重复。

实际 smoke 的两轮验证准确率均为 10%，验证 loss 很大，属于小规模运行不稳，不能当作收敛通过。正式训练从独立保存的初始状态开始，没有续用 smoke 训练后的权重；正式结果与 smoke 异常分别记录在上述分析中。

继续使用当前项目的 .venv，无需重新安装依赖或下载数据。命令在项目根目录的 PowerShell 中逐条执行。

实现位置如下。

| 文件 | 作用 |
|---|---|
| configs/e1.json | E1 独立配置，model=cifar_resnet18 |
| src/models/cifar_resnet.py | 32×32 ResNet-18、分类头 Dropout 0.3、显式初始化 |
| src/models/factory.py | E0/E1 共用模型选择、checkpoint 标识核验、初始状态哈希 |
| train.py | 按模型配置训练、保存起点、best/last 与续训 |
| evaluate.py | 自动构建权重对应的模型，默认评估验证集 |
| compare_runs.py | 对齐 E0/E1 的日志与验证预测，生成对照结果 |
| benchmark_models.py | 在同设备、同精度和相同合成输入下比较推理计时 |

E1 使用入口 3×3、stride=1、无入口最大池化，四个残差阶段 [2,2,2,2]，通道 64/128/256/512；GAP 后 Dropout(0.3) 和 Linear(512,10)。参数量 11,173,962。模型直接构建结构，不下载或使用预训练权重。各阶段输出尺寸为 32/16/8/4。

主训练设置与 E0 保持一致：100 轮、batch=128、SGD lr=0.1、momentum=0.9、weight decay=0.0005、余弦衰减至 0.00001、普通交叉熵、AMP、num_workers=0、seed=42；复用同一数据划分、归一化和基本增强。

**第一步：阅读配置，执行一次真实数据 smoke。**

```powershell
.\.venv\Scripts\python.exe -u train.py --config configs/e1.json --smoke
```

预期使用 GPU，对 1,000 张训练图片、500 张验证图片、500 张干净训练监测图片运行 2 轮，输出到 runs/E1/smoke_seed42/。两轮 smoke 的余弦总长度为 2，只用于检查流程；准确率不用于 E0/E1 架构结论。

初始化时会显示“正在加载训练依赖”和“正在校验 E1 数据清单”。首次导入 PyTorch/torchvision 可能较慢，让初始化正常完成即可。

检查终端是否有有限 loss、训练/验证指标与正常的模型保存。可查看曲线：

```powershell
.\.venv\Scripts\python.exe plot_history.py --run-dir runs/E1/smoke_seed42
```

已有目录会拒绝覆盖。若 smoke 已完成，无需再次重复；需要另一次独立检查时可加 --run-name smoke_check2。若中断后恢复 smoke，应同时保留 --smoke --resume。

**第二步：流程确认后，一次完成正式 100 轮。**

```powershell
.\.venv\Scripts\python.exe -u train.py --config configs/e1.json
```

正式结果独立保存在 runs/E1/seed42/。程序新建模型并重置种子，从随机初始化开始，不会接着 smoke 权重训练，也不会覆盖 E0。每轮都会做固定训练监测与验证，并按验证准确率保存 best.pt；last.pt 用于恢复最近完整轮次。

当前不预先承诺总小时数。模型参数更多，但参数倍数不是时间倍数；观察正式数据的实际轮耗时再估算。已做的 GPU 合成检查确认 batch=128、AMP、确定性设置下可完成前后向与更新；它不代替真实数据 smoke。

发生中断后使用：

```powershell
.\.venv\Scripts\python.exe -u train.py --config configs/e1.json --resume
```

总计划仍为 100 轮；完成后再次续训会提示已完成，并保留原有文件。续训要求当前配置与保存配置匹配。对于新运行，initial.pt 必须保留，程序会核对模型、配置、数据与实际初始参数哈希。初始状态文件缺失或内容被改动会拒绝续训，避免起点失去可追溯性。

**第三步：训练结束后生成曲线与验证集结果。**

```powershell
.\.venv\Scripts\python.exe plot_history.py --run-dir runs/E1/seed42
.\.venv\Scripts\python.exe evaluate.py --checkpoint runs/E1/seed42/best.pt
```

评估默认使用完整 validation，不访问测试集。输出位于 evaluation_validation_epoch最佳轮次/，包括总体/每类指标、预测 CSV、计数与归一化混淆矩阵、高置信错误图。最佳轮次由真实结果决定，不一定是 100。

旧 E0 权重仍可被识别：缺少 model 字段时默认为 simple_cnn。新的显式 --output-dir 参数可把评估写到独立目录；为避免覆盖，它只接受不存在或为空的目录。默认评估路径允许对同一结果重新生成图表，行为与 E0 阶段一致。

**第四步：生成 E0/E1 对照。**

```powershell
.\.venv\Scripts\python.exe compare_runs.py --run-dirs runs/E0/seed42 runs/E1/seed42
```

先确保两组均完成训练，且最佳权重已经生成默认位置的验证集结果。E0 已有的 evaluation_validation_epoch100/ 可以继续使用。

工具先核对共享数据清单、训练配置、实际学习率轨迹、完整日志、模型选择规则及验证预测，然后按图片原始索引对齐。结果默认写到 results/E0_vs_E1/：

| 输出 | 含义 |
|---|---|
| comparison.json / comparison.csv | 准确率、Macro-F1、最佳轮次、泛化差距、参数量、记录耗时等 |
| per_class_comparison.csv | 每类 Recall/Precision/F1 及 E1−E0 的百分点差 |
| paired_predictions.csv | 两模型对同一张验证图片的预测及正误变化 |
| curves.png | 两组训练目标、干净训练/验证指标和学习率叠加图 |

如果预测 CSV 的行序不同，工具会按原始索引对齐；如果数据、真实标签、训练协议或评估结果不一致，则明确报错，不混合不公平的比较。输出目录必须独立于两个输入运行目录，不能覆盖输入或其父目录。

**第五步：需要比较实际推理成本时，再统一计时。**

```powershell
.\.venv\Scripts\python.exe benchmark_models.py --checkpoints runs/E0/seed42/best.pt runs/E1/seed42/best.pt
```

默认使用 CUDA、FP32 张量、相同 32×32 合成输入，分别测 batch=1 和 128；每个 batch 先预热 10 次，再做 3 组各 50 次前向，交替模型测量次序，CUDA 在计时边界同步。报告记录 TF32 后端开关。

结果写入 results/E0_vs_E1/inference_benchmark.json，包含各次 batch 延迟、中位数、吞吐率及摊销每图时间。计时不含图片预处理或 CPU→GPU 传输；batch=128 的摊销每图时间不等同于 batch=1 单请求延迟。历史训练总时长受数据加载和负载影响，不能直接替代这个推理对照。

**训练目录中的新增记录。**

- initial.pt：第 0 轮真实起点，包含模型、配置、数据清单哈希、随机状态与初始参数内容 SHA256。后续 E5/E6 可复用共享参数，不凭同 seed 猜测初始权重一致。
- source_snapshot/：本次训练源文件副本与原始输入配置；environment.json 记录对应哈希。
- 新 checkpoint 和 summary 保存 model_name、initial_state_sha256；GPU 运行还保存 peak_cuda_allocated_mib，为各段运行的 PyTorch 张量峰值分配量，不是整个系统显存占用。
- 旧 E0 在训练时没有保存 initial.pt，兼容读取时允许起点哈希缺省，不会事后伪造旧起点。E0 的原代码已另存 source_snapshot_before_e1/，原权重与日志保留。

**结果分析口径。**

E0 当前最好验证准确率为 93.46%。E1 的结果要实际运行后填写：如果更高，要看提升集中在哪些类别以及成本；若相近，要比较大小和效率；若更低，应如实分析共享训练设置的适配性。

两组是相同数据遍历预算和增强策略的架构整体比较，并非同算力比较，也不单独隔离残差连接的作用。相同 seed 不保证不同架构逐图获得相同随机裁剪/翻转；单次 seed 42 也不能代表多种子稳定性。需要更强结论时，再为 E0/E1 都补 43、44。

测试集仍留到全部实验及模型选择方案冻结后统一评估。当前 E1 实现检查结果位于 results/implementation_checks/E1/；正式 E1 性能以未来 runs/E1/seed42/ 的实际训练记录为准。
