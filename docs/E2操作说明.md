**E2 操作说明：关闭随机裁剪和水平翻转，与 E1 比较基础增强**

截至 2026-11-17，E2 已完成正式 100 轮。最佳权重来自第 84 轮，完整验证复算准确率为 89.52%，比 E1 的 95.30% 低 5.78 个百分点；第 100 轮为 89.34%。完整结果见 [E1/E2 增强消融分析](../results/E1_vs_E2/analysis.md)。下述步骤保留供理解过程和复现，现有训练无需重复；继续使用项目现有 .venv 和 CIFAR-10 数据，无需安装新依赖。

**实验改变了什么。**

| 设置 | 已完成的 E1 | 已完成的 E2 |
|---|---|---|
| 模型 | CIFAR ResNet-18 | 相同，11,173,962 个参数 |
| 训练随机裁剪 | 开启，32×32、padding=4 | **关闭** |
| 训练随机水平翻转 | 开启，p=0.5 | **关闭** |
| 张量转换、归一化 | 保留 | 保留，使用相同训练统计量 |
| 训练顺序 shuffle | 开启 | 开启 |
| 验证与训练监测 | 无随机增强 | 相同 |
| 起始模型 | E1 保存的随机初始状态 | 加载 E1 第 0 轮 initial.pt 的同一状态 |
| 数据与种子 | train=45,000、val=5,000、monitor=5,000；seed=42 | 相同 |
| 训练预算 | 100 轮，batch=128 | 相同 |
| 优化与损失 | SGD，lr=0.1，momentum=0.9，weight decay=0.0005，普通交叉熵 | 相同 |
| 学习率与正则化 | 余弦至 0.00001、Dropout=0.3、AMP | 相同 |

E2 的训练图片不再随机改变位置或左右朝向，但模型的 Dropout 和 BatchNorm 仍按原设计工作。关闭图片增强不等于关闭所有正则化。

**一、查看配置与起点。**

新增配置为 [configs/e2.json](../configs/e2.json)，关键字段是：

```json
{
  "experiment": "E2",
  "model": "cifar_resnet18",
  "train_augmentation": false,
  "initial_checkpoint": "runs/E1/seed42/initial.pt",
  "output_dir": "runs/E2"
}
```

这里的 initial.pt 是 E1 尚未训练的第 0 轮模型。程序只加载模型参数和 BN 缓冲状态，重新创建 E2 的优化器、调度器和 AMP scaler，从第 1 轮训练；不会接着 E1 的第 96 或 100 轮继续。它会核验来源为正式 E1、第 0 轮、同模型、同数据清单、同种子和 Dropout，以及参数内容哈希。缺少该文件时应恢复对应的 initial.pt，不能改用 best.pt 或 last.pt。

本地核验得到 E2 起始状态与 E1 一致，SHA256 为：

```text
0d7d998dce998061a1710cdb2cf553a5fe77a7636a59d29e66d0acc38beba0ad
```

E0/E1 的旧配置缺少 train_augmentation 时仍默认开启增强；旧 checkpoint 与原配置文件保留。E2 明确要求 false，防止名为 E2 却仍在使用增强。

**二、启动正式 100 轮。**

在 PowerShell 中执行：

```powershell
# 在项目根目录打开 PowerShell
.\.venv\Scripts\python.exe -u train.py --config configs/e2.json
```

启动时应显示模型为 cifar_resnet18、模式为正式 E2、train=45000 / validation=5000 / monitor=5000，以及“训练增强：关闭（仅张量转换与归一化）”和 E1 第 0 轮初始参数哈希。首次导入依赖和校验数据需要等待，让程序完成初始化。

训练输出独立保存在 runs/E2/seed42/。保留以下文件：

| 文件 | 用途 |
|---|---|
| config.json、data_manifest.json、environment.json | 实际配置、数据索引和环境 / 源文件哈希 |
| source_snapshot/ | 本次训练代码和原始配置 |
| initial.pt | E2 自己保存的第 0 轮状态及 E1 来源信息 |
| best.pt | 按验证准确率、再按验证 loss 选择的最佳权重 |
| last.pt | 最近完成轮次及优化器、调度器、随机状态，用于恢复 |
| history.csv | 逐轮训练、监测、验证与计时 |
| summary.json | 最佳结果、完成状态、增强开关和初始化来源 |

CSV 沿用历史列名 train_aug_accuracy，以保持旧工具兼容；在 E2 中它表示当前无图片增强训练输入下的准确率。训练时的 Dropout / BN 与评估模式不同，这个指标和干净训练监测指标仍应分开理解。

如果你希望先手动跑两轮小规模流程，可改为：

```powershell
.\.venv\Scripts\python.exe -u train.py --config configs/e2.json --smoke
```

它只使用 1,000 / 500 / 500 张训练、验证、监测图片，输出到独立的 runs/E2/smoke_seed42/。之后正式命令仍从相同第 0 轮起点开始。smoke 的两轮余弦调度和小样本表现不用于 E1/E2 性能结论；不要为追求 smoke 准确率而改变正式 E2 的学习率或模型。

**三、中断后恢复。**

```powershell
.\.venv\Scripts\python.exe -u train.py --config configs/e2.json --resume
```

总预算仍为 100 轮。恢复使用 E2 自己的 initial.pt 和 last.pt，已开始的运行不需要再次读取外部 E1 初始文件。不要更改配置中的增强、种子、起点路径或总轮数；程序会拒绝配置不匹配的续训。输出目录已存在时，新训练会拒绝覆盖；已完成 100 轮后重复 --resume 会提示完成并保留原有结果。

**四、完成后生成曲线并评估最佳权重。**

```powershell
.\.venv\Scripts\python.exe plot_history.py --run-dir runs/E2/seed42
.\.venv\Scripts\python.exe evaluate.py --checkpoint runs/E2/seed42/best.pt
```

默认只评估完整验证集。输出到 runs/E2/seed42/evaluation_validation_epoch最佳轮次/，包括总体指标、每类 precision / recall / F1、逐图预测、混淆矩阵和错误图片。最佳轮次不一定是 100。

**五、与 E1 对照。**

E1 已有完整验证结果。E2 完成上述评估后执行：

```powershell
.\.venv\Scripts\python.exe compare_runs.py --run-dirs runs/E1/seed42 runs/E2/seed42
```

默认输出到 results/E1_vs_E2/，保留既有 results/E0_vs_E1/。导出 comparison.json / comparison.csv、per_class_comparison.csv、paired_predictions.csv 和 curves.png。报告明确标记 comparison_kind=augmentation，以及 E1 的增强为 true、E2 为 false；同时检查两组模型、参数量、初始状态哈希、数据划分和其他训练协议相同。

本命令的差值为 **E2 − E1**。E1 当前最佳验证准确率为 95.30%：差值为负，表示本次条件下去掉基础增强后表现下降；差值为正，表示本次去掉增强后表现提高。应同时观察验证 loss、每类指标、训练与验证差距及完整曲线，不能只凭一轮训练准确率判断。

E2 同时去掉裁剪和翻转，回答的是这组基础增强的整体作用，不能分别量化两者的贡献。当前只有种子 42，独立多种子重复仍按原完整计划后续安排；官方测试集留到实验和模型选择方案冻结后统一评估。
