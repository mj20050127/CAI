**E4 实验方案：基础增强 + CutMix**

方案创建于 2026-11-17。E4 已按此方案实现，并在 `runs/E4/seed42_retry1` 完成 100 轮。第 97 轮最佳验证准确率为 96.30%。本文保留设计约定。运行说明与结果见 [E4操作说明](E4操作说明.md) 和 [E4 对照分析](../results/E1_vs_E4/analysis.md)。

**一、目标与对照关系**

E4 使用 CIFAR ResNet-18，保留 E1 的随机裁剪和水平翻转，加入 CutMix，关闭 MixUp，不叠加标签平滑、注意力或其他新增方法。

| 实验 | 基础裁剪 / 翻转 | 混合增强 | 当前最佳验证准确率 |
|---|---|---|---:|
| E1 | 开启 | 无 | 95.30% |
| E3 | 开启 | MixUp，alpha=0.2 | 95.62% |
| E4 | 开启 | CutMix，alpha=1.0 | 96.30% |

主对照为 **E1 / E4**，研究当前共享方案下加入 CutMix 的效果。补充对照为 **E3 / E4**，比较预设的 MixUp 与 CutMix 两套增强方案。两者 alpha 和有效混合强度不同，不能称为完全匹配混合强度的实验，也不能代表各自充分调参后的性能上限。

E4 从 E1 保存的第 0 轮 initial.pt 开始，不从 E3 的 best.pt 或 last.pt 接着训练。E2 / E4 同时改变基础增强与混合增强，不作为主单因素对照。

**二、CutMix 做什么**

把图片 B 的一个矩形区域贴到图片 A 的相同位置，用 B 的内容替换 A 该区域；标签按替换区域面积混合。与 MixUp 的整图像素加权不同，CutMix 保留各区域中原有的像素内容。方法来源为 [CutMix 原论文](https://arxiv.org/abs/1905.04899)。

例如，32×32 的图片最终实际替换了 16×16 的区域：B 占 256/1024=25%，则目标为 A 类 75%、B 类 25%。这个比例由最终区域决定，并不保证等于最初抽取的比例。

拟定的 batch 流程为：

1. 训练图片先执行现有 RandomCrop(32,padding=4)、水平翻转、ToTensor、Normalize。
2. 在 batch 内随机排列配对，得到原标签 yA 和配对标签 yB。
3. 抽取 lambda_raw ~ Beta(1.0,1.0)，用于确定候选矩形大小；本轮每个 batch 执行。
4. 矩形宽、高比例均取 sqrt(1−lambda_raw)，随机抽取中心，按下述整数规则生成矩形并裁剪到图像范围。
5. 从未修改的原 batch 取 B 的同位置区域，贴到 A 的副本上。
6. 根据最终矩形面积重算 lambda_eff，并用它同时计算标签损失及加权训练准确率。

每个 batch 共用一个矩形和候选比例，每张图片的来源 B 由随机排列决定。允许同类、自身配对和极小替换区域，不为制造明显拼贴效果而重新抽样。

**三、最关键的正确性约定：按实际面积修正标签**

张量采用 NCHW：H=shape[-2]，W=shape[-1]。矩形采用半开切片 [y1:y2,x1:x2]。标签权重为：

```text
actual_area = (x2 - x1) * (y2 - y1)
lambda_eff = 1 - actual_area / (W * H)
loss = lambda_eff * CE(logits, yA)
       + (1 - lambda_eff) * CE(logits, yB)
```

这一面积修正与 [作者实现](https://github.com/clovaai/CutMix-PyTorch/blob/master/train.py)中的原则一致。不能直接把 lambda_raw 当作最终标签权重；边界裁剪和整数取整都会改变实际面积。

本项目拟明确以下取整政策，避免奇数边长歧义：

```text
cut_w = floor(W * sqrt(1 - lambda_raw))
cut_h = floor(H * sqrt(1 - lambda_raw))
left = cx - cut_w // 2
top  = cy - cut_h // 2
right = left + cut_w
bottom = top + cut_h
x1/x2 = 分别将 left/right 裁剪到 [0,W]
y1/y2 = 分别将 top/bottom 裁剪到 [0,H]
```

这是一套显式的项目整数框约定；奇数边长的两侧分配不依赖隐含取整。矩形越界后面积变小属于正常情况，实际 lambda_eff 的分布也不再等同于原始 Beta 抽样。空区域对应 lambda_eff=1，整图替换对应 0，均应正确处理。

混合使用原 batch 的副本，确保 B 的来源内容未被之前的替换污染，原输入保持不变。输出仍使用 logits，不先做 softmax；加权两份标签的交叉熵等价于对应软标签交叉熵。

**四、固定训练设置**

| 项目 | E4 设置 |
|---|---|
| 模型 | CIFAR ResNet-18，11,173,962 个参数，输入 3×32×32 |
| 初始状态 | 对应种子 E1 的 initial.pt；首轮为 runs/E1/seed42/initial.pt |
| 数据 | train=45,000，validation=5,000，monitor=5,000；复用原索引和归一化 |
| 种子 | 训练 42，划分 2026，监测 2027 |
| 基础增强 | 随机裁剪 padding=4，水平翻转 p=0.5，训练 shuffle 开启 |
| CutMix | alpha=1.0，应用概率=1.0，每 batch 一个矩形 |
| MixUp / 标签平滑 | 关闭 / 不使用 |
| 轮数 / batch | 100 / 128，最后不足一批仍正常使用 |
| 优化器 | SGD，lr=0.1，momentum=0.9，weight decay=0.0005 |
| 调度 | 100 轮余弦衰减至 0.00001 |
| 模型正则化 | Dropout=0.3，原有 BN 不变 |
| 运行环境 | 当前 .venv、CUDA、AMP、num_workers=0；无需新增依赖 |
| 监测与验证 | 每轮一次，固定无随机增强图片、原始标签普通交叉熵，不应用 CutMix |
| 最佳模型 | 验证准确率最高；平局时验证 loss 更低，再平局保留较早轮次 |
| 测试集 | 当前不评估，留到全部实验和模型选择方案冻结后 |

E3 后期仍有慢改善，不构成单独把 E4 改成 200 轮的依据。本轮先保持相同 100 轮预算；更长训练另设成组对照并保留原结果。

**六、日志、随机状态与可复核性**

逐批保存到拟新增的 cutmix_batches.csv：epoch、batch、lambda_raw、lambda_eff、x1/y1/x2/y2、actual_area、applied。矩形为离散像素框，必须能够用坐标重新计算同一个面积和标签比例。

history.csv 保存本轮应用批数、总批数、实际 lambda 的均值 / 最小 / 最大值，以及单独命名的 train_cutmix_weighted_accuracy。其计算为 lambda_eff×对 yA 正确数 + (1−lambda_eff)×对 yB 正确数，再除以样本数，不能用混合图片只对原标签计算普通准确率。

CutMix 采样、配对和随机中心沿用主进程 NumPy 随机状态；checkpoint 已保存 NumPy、Torch、CUDA 和各 DataLoader 状态。新日志也进入 checkpoint，恢复时从最近完整轮次重建 CSV，避免中断造成重复或丢失记录。

CutMix 同样有软标签熵，训练 loss 不要求趋近 0；不同混合强度下的训练 loss 和加权训练准确率不能直接用于排列 E1/E3/E4。统一关注干净训练监测、验证准确率、验证普通 CE、Macro-F1 和每类结果。

正式每轮 352 批，完整 100 轮应有 35,200 条 batch 记录。若实际替换面积为 0，应用标记与实际面积分别保存，不把“尝试执行”和“发生非零替换”混为一谈。

**七、先验证，再由用户训练**

必要检查分为：

1. 固定配对、矩形，验证只有指定区域被替换，其他像素和原 batch 不变。
2. 验证奇数边长、四边裁剪、空区域、整图、非正方形 H/W、单样本和末批；标签比例严格等于实际面积。
3. 验证加权损失及梯度等价于软标签交叉熵，加权准确率按真实 batch 大小汇总；验证 / monitor 不混合。
4. 验证 E0–E3 默认行为兼容，MixUp/CutMix 不同时开启，已有配置和 checkpoint 可继续使用。
5. 使用 CPU 合成数据验证连续训练与分段续训的权重、矩形、实际比例和日志一致；更改配置后拒绝混用原续训目录。
6. 核验 E4 实际初始模型内容哈希与 E1 一致；检查同一数据划分和归一化。
7. 用一个 GPU 合成 batch=128、AMP 检查有限损失、有限梯度和实际参数更新。
8. 生成真实训练图片示例，查看矩形、替换结果和面积标签；之后由用户启动正式训练。

示例与检查不访问测试集，不预先填入 E4 的准确率。小规模 smoke 可作为手动流程检查，不为追求两轮准确率而改变本次对照设置。

分析优先回答：

- 相比 E1 的 95.30%，验证准确率、Macro-F1、错误数是否改善？
- 相比 E3 的 95.62%，当前 CutMix 方案在什么类别或指标更好 / 更差？
- 猫狗混淆是否继续减少，鸟的 precision / recall 是否更均衡，鹿和船是否出现退化？
- 干净训练监测与验证的差距、最后 10/20 轮走势怎样，是否还有慢改善？
- 参数量、训练时间、峰值显存和稳定性对应什么代价？历史耗时不能替代严格速度基准。

E4 结果较低也要保留，作为增强方向的真实对照。单种子较小差异不直接当作稳定优势；关键候选的多种子复核仍按完整实施计划安排。参数量和推理结构保持相同，训练时间以实际测量为准，不提前承诺精确耗时。
