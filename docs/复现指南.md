# 实验复现指南

实验二位于 [CAI的lab2分支](https://github.com/mj20050127/CAI/tree/lab2)，首页提供直接克隆该分支的命令。本指南从该分支的仓库根目录开始。先确认四题和测试，再根据目的选择小规模检查、重新汇总已有批次，或重新采集正式规模数据。除特别说明，代码块中的命令可以在PowerShell或bash逐行执行。

## 一 环境准备

### 解释器与依赖

核心算法与测试支持Python 3.10及以上，仅用标准库。固定的Matplotlib 3.11.2要求Python 3.11及以上，完整实验建议采用原采集时的Python 3.13.9。

先检查所用解释器：

```bash
python --version
python -c "import sys; print(sys.executable)"
```

Windows PowerShell可建立并激活虚拟环境：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-experiments.txt
```

若系统策略不允许激活脚本，可直接用虚拟环境中的解释器，无需修改系统策略：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-experiments.txt
.\.venv\Scripts\python.exe -m src.main --case all
```

此时后续所有 `python` 均替换为 `.\.venv\Scripts\python.exe`。

macOS或Linux可使用：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-experiments.txt
```

确认绘图库版本：

```bash
python -c "import matplotlib; print(matplotlib.__version__)"
```

预期为3.11.2。`python -m pip`可保证安装依赖与运行实验使用同一解释器。依赖文件没有锁定所有间接依赖、系统字体与操作系统，跨环境PNG不保证逐字节相同。中文图表优先查找微软雅黑、黑体、Noto Sans CJK SC等字体；缺字体时可先查看保存的原图，再配置可用中文字体后重绘。

### 先通过基础检查

```bash
python -m src.main --case all
python -m unittest discover -s tests -v
```

当前版本应输出题一7步、题二代价7、题三根值5、题四H=2为T2/-1且H=4为T3/3，并显示139项测试通过。任一步失败时先处理环境、目录或输入问题，再运行性能实验。

## 二 小规模检查采集与审计流程

下面两条命令分别检查“生成新迷宫”和“固定官方博弈输入”的采集流程。它们只依赖标准库：

```bash
python -m experiments.exp1_heuristic --sizes 7 --instances 2 --batches 1 --warmup 1 --max-loops 1 --no-analysis --out runs/smoke_maze
python -m experiments.exp4_gain --input results/problem4_gain/input/problem4.json --batches 1 --warmup 1 --max-loops 1 --no-analysis --out runs/smoke_gain
```

第一次运行时目录须不存在或为空。运行成功后应有 `config.json`、`raw.csv` 及输入/审计材料；配置中的采集 `status` 应为 `completed`，`analysis_status` 为 `skipped`。Gain小检查的 `raw.csv` 有2行：原序与动态排序各1批。

`--no-analysis` 只跳过后续汇总与绘图，不跳过正确性审计，也不会自动减少输入规模。这些极少批次的输出用于检验流程，不能据此写正式性能结论。再次执行请换输出名，如 `runs/smoke_gain_02`。

若要随后给小检查补画图，先安装绘图依赖，再执行：

```bash
python -m experiments.analyze_maze_heuristics --results runs/smoke_maze
python -m experiments.analyze_treasure_gain --results runs/smoke_gain
```

## 三 复制已有结果后重新汇总绘图

分析器读取保存的正式批次，不重新采集性能数据，但会重写目标目录中的汇总CSV/JSON、PNG/SVG及 `config.json` 的分析状态、时间等字段。它们不是只读核验工具。

先复制整个结果目录，再分析副本。例如题四Gain：

```bash
python -c "from shutil import copytree; copytree('results/problem4_gain', 'runs/reanalysis_gain')"
python -m experiments.analyze_treasure_gain --results runs/reanalysis_gain
```

`copytree`在目标已存在时会拒绝复制。第二次操作改用新的副本名称。必须复制整轮目录，不能只复制 `raw.csv`；输入、轨迹、配置、源码归档等都可能参与审计。

完成后，副本中的 `config.json` 应显示 `analysis_status=completed`，并生成或更新 `gain_summary.csv`、`gain_analysis.json`、`figures/`。`raw.csv` 的字节和旧计时保持不变；变化的是派生汇总、图表与分析元数据。其他轮次的分析器对应关系如下：

| --- | --- | --- |
| `problem1_heuristics` | `experiments.analyze_maze_heuristics` | `summary.json`、`summary.csv`、`paired.csv` |
| `problem2_heuristics` | `experiments.analyze_weighted_heuristics` | `summary.json`、`summary.csv`、`paired.csv` |
| `problem2_lookahead` | `experiments.analyze_lookahead` | `summary.json`、`summary.csv`、`paired.csv` |
| `problem2_lookahead_optimized` | `experiments.analyze_lookahead_optimized` | `summary.json`、`summary.csv`、`paired.csv` |
| `problem2_two_step_optimized` | `experiments.analyze_two_step_optimized` | `summary.json`、`summary.csv`、`paired.csv` |
| `problem3_minimax_alpha_beta` | `experiments.analyze_game_tree` | `summary.json`、`summary.csv`、`paired.csv` |
| `problem3_visit_order` | `experiments.analyze_visit_order` | `summary.json`、`tree_summary.csv`、`paired.csv` |

## 四 复用保存输入进行正式规模复测

仓库已保存全部实际输入，各条命令都能独立执行，无需为了复测后续轮次先重跑前一轮。以下命令重新采集数据并默认自动分析、绘图，因此需安装绘图依赖。

所有 `runs/replay_*` 目录均用于首次执行；重复运行请改名。不要把 `--out` 改回已有的 `results/` 正式目录。正式规模包含较多查询，耗时取决于机器；应等待采集和分析都完成。

### 题一 零启发与曼哈顿

```bash
python -m experiments.exp1_heuristic --dataset results/problem1_heuristics/dataset --out runs/replay_problem1_heuristics
```

输入为21/51/101边长各30张保存的可达迷宫，官方图单列。实际地图及被拒绝候选已保存，复测不重新随机生成。

### 题二 基础性质与前瞻优化

按下列顺序阅读；因为输入已经随仓库提供，执行时可以只选想验证的一轮：

```bash
python -m experiments.exp2_weighted_terrain --dataset results/problem2_heuristics/dataset --out runs/replay_problem2_heuristics
python -m experiments.exp2_lookahead --dataset results/problem2_heuristics/dataset --out runs/replay_problem2_lookahead
python -m experiments.exp2_lookahead_optimized --dataset results/problem2_lookahead/dataset --out runs/replay_problem2_lookahead_optimized
python -m experiments.exp2_two_step_optimized --dataset results/problem2_lookahead/dataset --out runs/replay_problem2_two_step_optimized
```

共同复用30张31×31加权地图，官方图单列。基础轮比较零/原始/安全修正；后续分别比较前瞻深度、一步等值实现和两步等值实现。原始曼哈顿在给定输入上算对不等于可采纳，须同时核查性质审计。

### 题三 剪枝与访问顺序

```bash
python -m experiments.exp3_minimax_alpha_beta --dataset results/problem3_minimax_alpha_beta/dataset --out runs/replay_problem3_minimax_alpha_beta
python -m experiments.exp3_visit_order --dataset results/problem3_minimax_alpha_beta/dataset --out runs/replay_problem3_visit_order
```

复用同一批三叉树：深度4/6/8各30棵，官方树单列。第二轮每树比较原序、10个固定随机序与真值序，随机顺序是同一输入内的重复，不是新增独立树。

### 题四 深度与两种排序

```bash
python -m experiments.exp4_depths --input results/problem4_depths/input/problem4.json --out runs/replay_problem4_depths
python -m experiments.exp4_order --input results/problem4_order/input/problem4.json --out runs/replay_problem4_order
python -m experiments.exp4_gain --input results/problem4_gain/input/problem4.json --batches 10 --out runs/replay_problem4_gain
```

第一轮包括距离核验、H=1至4及矩阵复用/端到端两种范围；第二轮固定H=4枚举24种全局优先级；第三轮在同一实现中比较原序和即时Gain动态排序。三轮绝对计时不混用。

### 正式参数与输入依赖

大多数轮次默认正式5批，Gain为10批；预热2次，校准循环数的目标批时25 ms、慢者估计上限200 ms、最多128次。具体调用数由校准决定，复测不要求与旧轮相同。

使用 `--dataset` 时，输入规模、分布和种子以已保存的manifest为准；额外写 `--instances 1` 或新的 `--seed` 不会把已有整批输入自动截成小样本。快速检查请使用上一节的“小图且不带--dataset”命令。

题一、题二基础轮复用dataset时，新输出通过相对路径引用源输入，不再复制随机dataset；不能单独搬走它们的 `runs/` 结果目录。其余题二前瞻、题三实验会复制dataset，题四会复制官方input。复现时应保留整个仓库结构，不手改CSV和config中的路径、哈希。

如果希望从零生成新输入，可先在题一、题二基础轮或题三基础轮不传 `--dataset`，再把后续轮次的 `--dataset` 指向相应新输出的dataset。题二按“基础→前瞻→实现优化”、题三按“基础→顺序”衔接，保持每次对照使用相同输入。

所有测量器均支持 `--no-analysis`。如暂不绘图，可把它追加到复测命令末尾；采集完成后安装依赖，再以第三节表中的对应分析器处理该新结果目录。

## 五 如何判断复现成功

| 层次 | 应核查的内容 | 不应强求相同的内容 |
| --- | --- | --- |
| 基础正确性 | 官方结果与139项测试通过 | 不同合法最短路径的坐标字符串 |
| 相同输入 | 地图/树/输入JSON及manifest的哈希 | 新运行的run_id和时间戳 |
| 相同搜索配置 | 最优代价、根值、首步与确定性节点数 | 不同并列规则、启发或顺序配置的访问计数 |
| 测量完整性 | `config.json` 采集状态completed、批次数齐全、审计通过 | 校准出的循环次数、所有毫秒数 |
| 分析完成 | 分析状态completed、汇总文件与figures生成 | PNG字节、字体布局及分析完成时间 |

`--no-analysis` 时分析状态skipped符合预期。一般轮次读 `summary.json`；题四固定顺序读 `analysis.json`，Gain读 `gain_analysis.json`。原始行在 `raw.csv`，等值优化另有equivalence/proof等核查材料，详见各轮分析文档。

正确性、确定性计数与统计趋势应分别判断。性能表以同一输入内配对为主，先在输入内汇总重复批次，再跨独立输入汇总；不能将不同轮次的绝对时间拼表，也不能把四分位范围当作置信区间。单次 `--stats`、小规模检查与正式配对结果不可混作一种证据。

## 六 保留原始证据和检查文件完整性

`results/` 中的原始数据、输入、源码归档保留不动。读取现有Markdown、JSON、CSV和PNG即可查看结果；分析器会修改所指目录，所以重绘应使用副本。

`MANIFEST.sha256` 覆盖发布时的文件，未包含其自身和之后生成的新运行。Windows PowerShell可在根目录检查：

```powershell
$taskMismatch = @(
    Get-Content -LiteralPath MANIFEST.sha256 -Encoding UTF8 | ForEach-Object {
        $taskExpected, $taskRelative = $_ -split '  ', 2
        $taskActual = (Get-FileHash -LiteralPath $taskRelative -Algorithm SHA256 -ErrorAction SilentlyContinue).Hash
        if ($taskActual -ne $taskExpected) { $taskRelative }
    }
)
if ($taskMismatch.Count -eq 0) {
    '所有清单文件校验通过'
} else {
    $taskMismatch
    throw '有文件缺失或内容发生变化'
}
```

Linux可使用 `sha256sum -c MANIFEST.sha256`。校验不通过不必然是算法错误；例如直接重绘正式目录或编辑README都会改变相应发布文件。应区分完整性变化与结果正确性，保留自己的修改记录。

仓库的 `.gitattributes` 使用 `* -text` 禁止Git自动转换换行，保持LF/CRLF各文件的原始字节。上传时应一并包含它。请先从本副本建立仓库，避免编辑器保存或批量格式化改写现有源码及JSON/CSV。若曾在缺少该属性时通过Git自动转换过文件，应恢复原始副本再检查哈希，而不是修改expected哈希绕过检查。

分析器还会检查各轮源码和归档。当前上传副本的源码与10轮记录一致；今后修改源码后，如需核验旧轮，可在独立目录解压该轮 `source_baseline.zip`，保留其记录的目录结构和对应结果。不要删改哈希字段绕过核验。

## 七 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| `No module named src` 或 `experiments` | 回到含README、src和experiments的项目根目录，使用 `python -m` |
| 找不到matplotlib | 确认解释器≥3.11，使用同一个 `python -m pip install -r requirements-experiments.txt`；只采集时可用 `--no-analysis` |
| Python3.10安装绘图依赖失败 | 核心可用不代表固定绘图包可用；更换≥3.11的解释器，建议与原记录接近的3.13 |
| 输出目录非空 | 测量器拒绝覆盖；为 `--out` 换新的目录名，保留已有数据 |
| `copytree`提示目标已存在 | 换一个新的重绘副本名，不向已有目录叠加复制 |
| 加了 `--instances 1` 仍跑很多图 | `--dataset`采用已保存manifest；小检查应不传dataset，另行生成小输入 |
| 采集结束，绘图阶段失败 | 检查新目录config与raw是否完整；修复依赖/字体后直接运行对应分析器，不必再次用runner写入非空目录 |
| 输入或源码哈希不匹配 | 确认文件完整、原始换行、目录结构和源码版本；保留.gitattributes，按记录恢复源码/数据，不手改哈希 |
| 中文图显示方框 | 安装或配置代码支持的中文字体再重绘；数值审计与字体显示分别判断 |
| 新时间与报告不同 | 机器、解释器、依赖、系统负载、校准和缓存会影响耗时；先核查输入和确定性计数，再分析本轮配对数据 |
