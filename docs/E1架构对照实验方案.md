**E1 架构对照实验方案：自建 CNN 与 CIFAR 适配版 ResNet-18**

日期：2026 年 11 月 16 日。状态：E1 已按方案实现，真实数据 smoke 与正式 100 轮训练均已执行；最佳权重为第 96 轮，完整验证准确率 95.30%，E0 为 93.46%。性能与成本对照、smoke 异常和结论边界见 [结果分析](../results/E0_vs_E1/analysis.md)，操作见 E1操作说明.md。本文保留设计约定。

E1 的目标是在共享数据和训练方案下，将 E0 的自建六层卷积 CNN 换成 CIFAR 适配版 ResNet-18，比较分类效果、收敛过程和计算成本。它同时作为后续注意力、增强、损失及训练策略实验的共同基准。

本轮研究的问题是：“在相同训练数据、增强策略、100 轮训练预算和优化设置下，两个架构整体方案的效果与成本有何差异？”架构改变会同时带来深度、宽度、参数量、下采样方式和残差结构的变化，因此不能把所有性能差异单独归因为残差连接。同轮数也不代表同计算预算，不能把本实验当作两种架构分别充分调参后的性能上限比较。

E1 使用 torchvision 提供的 ResNet-18 主体，明确指定 weights=None，从随机初始化开始。它不使用 E0 训练后的权重或 ImageNet 权重。预训练效果留给原计划中的 E9/E10 对照。[官方 ResNet-18 接口说明](https://docs.pytorch.org/vision/0.23/models/generated/torchvision.models.resnet18.html)

考虑 CIFAR-10 的 32×32 输入，对标准入口进行两处适配：首层 7×7、stride=2 改为 3×3、stride=1、padding=1；取消入口最大池化。这样保留更多早期空间分辨率。保留四个残差阶段，每阶段两个 BasicBlock，输出通道依次为 64、128、256、512。BasicBlock 采用主分支与捷径相加后激活；尺寸或通道不一致时由投影捷径对齐。残差学习思想来自 [ResNet 原论文](https://arxiv.org/abs/1512.03385)。这些入口修改和下述 Dropout 是本实验的设计选择。

| 位置 | 结构 | 单张图片的输出形状 |
|---|---|---|
| 输入 | RGB 图片 | 3×32×32 |
| 入口 | 3×3 卷积，64 通道，BN、ReLU | 64×32×32 |
| stage 1 | 2 个 BasicBlock，64 通道 | 64×32×32 |
| stage 2 | 2 个 BasicBlock，128 通道，阶段入口降采样 | 128×16×16 |
| stage 3 | 2 个 BasicBlock，256 通道，阶段入口降采样 | 256×8×8 |
| stage 4 | 2 个 BasicBlock，512 通道，阶段入口降采样 | 512×4×4 |
| 全局平均池化 | 每通道汇总空间信息 | 512×1×1 |
| 分类头 | flatten、Dropout(0.3)、Linear(512,10) | 10 个 logits |

一个需要明确的控制项是 Dropout。E0 分类头使用 0.3，而标准 ResNet-18 分类头没有 Dropout。本方案建议 E1 也在全局池化后、全连接前加入 Dropout 0.3，尽量保持共享的正则设置。因此正式名称应写为“CIFAR 适配版 ResNet-18，分类头 Dropout 0.3”，不称未经改动的标准网络。相同概率并不意味着对不同特征维度产生完全相同的正则作用。若后来研究 dropout=0，应另存独立配置。

已在当前 torchvision 环境中，仅用 CPU 内存构造和随机输入前向核算上述候选结构：参数量为 **11,173,962**，约为 E0 的 **9.73 倍**，输出为 N×10。参数量增加不等同于运行时间增加相同比例；耗时、显存和推理速度需要实际测量。

共享归一化为 mean≈[0.491514,0.482315,0.446814]、std≈[0.247051,0.243480,0.261510]，实际使用 data/split_manifest.json 中的完整精度。E1 不重新划分或重新拟合归一化统计，不放大到 224×224。

初始化也采用与 E0 相同的规则：卷积权重使用 Kaiming normal、fan_out、ReLU；BatchNorm 的 weight=1、bias=0，初始运行均值为 0、方差为 1；全连接权重 N(0,0.01)，bias=0。替换后的入口卷积和分类层也执行这一规则；保持 zero_init_residual=False，不另引入残差分支零初始化技巧。相同规则与种子不意味着不同形状的参数具有相同初始数值。

复现方面需要区分“相同策略与种子”和“每张增强图片逐像素相同”。当前 num_workers=0 时，增强会使用全局 PyTorch 随机流，架构初始化等也会消耗随机数。DataLoader 的独立 generator 可以保持相同的 shuffle 规则，但不同模型不保证每次裁剪/翻转结果逐张一致。E1 首轮沿用现有数据实现，避免仅给 E1 换用一套新的增强协议。后续若强化随机流隔离，须作为统一版本应用并清楚记录。

第一阶段先做 seed 42 的直接对照，E0 已有结果可以复用。但单次运行只能说明本次配置下的差异。若准备声称某架构稳定更好，建议为 E0、E1 都补 seed 43、44，每个架构共三次，报告均值和标准差；只重复 E1 不能估计 E0 自身的波动。这会在当前两组 seed 42 之外增加四次正式训练，作为后续预算允许时的增强验证阶段，不在本次方案分析中自动执行。

编码阶段需要完成以下改动，确认方案后再实施。仅增加 E1 模型文件而不调整现有固定 SimpleCNN 的训练/评估入口是不够的。

| 拟议文件 | 目的 |
|---|---|
| configs/e1.json | E1 独立配置，模型标识、100 轮共享参数、输出 runs/E1 |
| src/models/cifar_resnet.py | 32×32 ResNet-18 适配、分类头与初始化 |
| src/models/__init__.py 或模型工厂模块 | 按配置构建 SimpleCNN 或 CIFAR ResNet-18 |
| src/common.py | 配置校验兼容模型标识及旧 E0 配置 |
| train.py | 使用模型工厂，日志标识由配置决定，保存模型标识和初始状态 |
| evaluate.py | 按 checkpoint 中的模型标识构建正确网络 |
| 对照汇总/绘图入口 | 输出 E0/E1 比较表、叠加曲线和样本错误变化 |
| tests/ | 模型接口、恢复、旧 E0 兼容及关键数据约束检查 |
| README.md | E1 分步操作与结果位置 |

配置拟新增可选 model 标识，例如 cifar_resnet18；旧 E0 配置缺少该字段时默认为 simple_cnn。配置比较、续训和评估均应做兼容处理，不能因为增加字段就使旧 E0 权重或配置失效。原 E0 配置、权重和结果文件不需要重写；实施前保留当前 E0 代码快照与原有哈希，后续新源码版本另行记录。

环境继续使用现有项目 .venv：Python 3.11.9、torch 2.8.0+cu126、torchvision 0.23.0+cu126。新增架构不要求安装新依赖或下载预训练权重。当前约 8 GB GPU 显存能否在实际实现下稳定运行 batch=128，先通过小规模检查确认。若确需改变 batch，应把条件差异明确记录或对两个架构统一设计新的对照，不能悄悄只改一组后归因于架构。

实施与运行分四步，正式阶段按用户偏好一次完成 100 轮，不再反复拆成 3、7、10 轮进行观察。

1. 完成代码与局部验证。检查各 stage 形状、参数量、N×10 logits、有限 loss/梯度、残差投影、AMP 和保存重载。验证旧 E0 best.pt 经新的模型工厂评估仍得到 93.46%。使用独立测试模型或重建模型，合成数据检查后的权重和 BN 状态不能成为正式起点。
2. 执行一次独立 smoke：1,000/500/500 样本、2 轮，确认 GPU、数据和输出路径。准确率不用于架构结论，也不与 E0 的两轮 smoke 分数比较高低。
3. 确认流程和显存后，重置种子并新建正式模型，保存初始权重，然后一次训练 100 轮。首轮与后续轮次记录时间，依据实际耗时更新预算；不能按参数量比例直接给出总小时数。训练仍逐轮验证、自动保存 best/last，发生中断可续训。
4. 对最佳权重只做验证集评估与 E0 对照，生成全部图表和分析。测试集保留到整体实验与选择规则冻结之后再统一评估。

.\.venv\Scripts\python.exe evaluate.py --checkpoint runs/E1/seed42/best.pt

正式 E1 使用 runs/E1/seed42/，smoke 使用 runs/E1/smoke_seed42/。保存完整配置、环境与源码哈希、数据清单、初始权重及哈希、best/last、逐轮 CSV、总结和验证预测。初始状态文件也为后续单项对照服务：E6 固定学习率实验可从与 E1 完全相同的初始状态开始；E5 加 CBAM 时复制 E1 的全部共享参数和 BN 缓冲，再单独初始化注意力模块。仅重新设置相同 seed 不足以保证模块插入后共享参数一致。

E0/E1 的最终比较同时包括效果、过程和成本。

| 维度 | 指标与口径 |
|---|---|
| 总体性能 | 最好验证准确率、其配套 loss、Macro-F1，报告差值的百分点 |
| 类别表现 | 每类 Recall/Precision/F1，重点跟踪猫、狗、鸟 |
| 错误变化 | 相同 5,000 张图片上，E0 错→E1 对、E0 对→E1 错的数量 |
| 训练轨迹 | 叠加两模型的 train objective、干净训练/验证 loss 与准确率 |
| 收敛过程 | 首次达到 90%、92%、93% 的轮次，若未达到则如实标注 |
| 泛化差距 | 相同干净训练监测集与验证集的准确率差值 |
| 模型大小 | 实际参数量、权重文件大小 |
| 训练成本 | 记录轮耗时和总耗时，明确含/不含哪些开销 |
| 推理成本 | 同设备、同精度、同分辨率、预热后同步计时，固定 batch 的延迟或吞吐率 |
| 复现性 | 配置、模型定义、划分、版本、初始状态和训练种子可追溯 |

E0 历史耗时在不同阶段曾有明显波动，因此两次训练的总时长只能提供实际运行成本参考。若要比较模型本身的推理速度，应在同一次测量环境中对两模型分别预热、同步并重复计时，不能仅用历史训练耗时断言哪个架构快多少。
